# Sample Governance folder structure

This is the **anonymized, empty** folder layout the PBIP Toolkit expects. No real
`.pbix` files are included — the `_PLACE-MODEL-PBIX-HERE.txt` markers show where
yours go (and exist only so Git keeps the otherwise-empty folders).

## Expected layout

```
Governance/
├── pbi-tools/                         <- installed by scripts/Install-PbiTools.ps1
└── WS/                                <- fixed folder name; the scanner keys off it
    └── <Workspace Name>/              <- one folder per Power BI workspace
        └── <Model Name>/              <- one folder per semantic model
            ├── <Model Name>.pbix      <- the semantic model
            ├── pbip_<Model Name>/     <- generated by the toolkit (pbi-tools extract)
            └── reports/               <- optional: live-connected report .pbix files
                └── <Report>.pbix
```

## Rules the scanner applies

- The `WS` folder name is required — a `.pbix` not located under `…/WS/…` is
  skipped or flagged as misplaced.
- A `.pbix` directly inside a workspace folder (no model subfolder) is reported
  as misplaced for one-click organizing.
- Any `.pbix` inside a `reports` subfolder is treated as a report, not a
  semantic model, and excluded from model counts.
- Workspace and dataset IDs are read from the `.pbix` itself (its `Connections`
  entry: `OriginalWorkspaceObjectId` and `RemoteArtifacts[0].DatasetId`).

This sample shows three workspaces — `Finance`, `Sales`, `Operations` — with a
few models and two `reports` folders, so you can see the shape before pointing
the toolkit at your real Governance root.
